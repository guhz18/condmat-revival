# Google Scholar 浏览器通道

这是用户要求的核心互补源。每次对材料作正式查新时必须完成或明确记录此通道的阻塞；不能因无批量API而静默删除。

## 正常交互路径

1. 使用当前环境可用的正式浏览器工具；有专用Browser技能则优先读取。初始化/导航/DOM或截图观察遵循该工具实时文档，不假设固定API名或DOM选择器。
2. 访问 Google Scholar 正常检索页，使用可见搜索框。先查热点同义词，再查具体材料。可用引号、OR和年份过滤；每次读取当前页面再选下一步。
3. 材料至少覆盖原化学式、约分式、旧名/结构型；必要时用原论文标题或作者查早期文献。
4. 检查 Cited by、Related articles、All versions 与合法全文链接；记录哪一条论文、哪个查询和哪一页支持发现。可使用页面提供的引用导出；不假定高级API存在。
5. 保存真实标题、作者、年、venue、DOI/arXiv（核对后）、公开目标URL、Scholar可复核查询、检索日期、页范围、已审查条目数、重要漏项。不要保存登录cookies/令牌或sorry页带会话参数的URL。
6. 原始论文为物理事实最终出处，Scholar是发现与引文追踪来源。引用总数与约X条命中仅为界面值，不当作精确、可重复的全库计量。
7. 同一材料下重复查询可命中近期缓存；新时间窗、别名或引用链补检按需做。避免无收益翻页；默认先审最相关2页和适用的近年页，实际范围写入日志，遇有明确证据缺口再继续。

## 访问限制

- 正常页面不需因读操作反复确认。不能通过代理轮换、破解验证码、窃取会话或规避安全控制获得访问。
- 明确异常流量/验证码/封禁时，按浏览器实时botDetection/CAPTCHA规则处理；最多一次允许的低风险恢复。需要用户完成验证时按工具允许的接管方式，不自行尝试未授权验证码操作。
- 记录status=blocked或failed、时间、原因及待补查询；不用0篇代替失败。主报告突出“Scholar待补检”，不宣称已接通成功。
- 如果浏览器当前不可用，保留查询队列；可以导入用户合法取得的Scholar导出记录，但注明来自导出与覆盖时间。这是替代的输入路径，不等于本次浏览器检索成功。
- 用户明确要求Scholar时，其他学术源只能并行补充，不能偷偷替代此要求。完成其余获授权工作，并说明当前限制及下一次可续接的位置。

## 运行状态

使用动态能力状态：available / blocked / unavailable / not_attempted。不要把某次云浏览器拦截固化为技能永久配置。实际每次运行写入searches及run notes；历史失败可用于避免同会话反复撞限。CLI `collect.py` 不抓Scholar；此通道由支持的浏览器工具执行。
